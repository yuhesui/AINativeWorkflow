# GPT56_ROUTING.md — Model and Surface Routing

Availability is product/runtime-declared, not inferred from a marketing name. Prompt and run logs record the exact visible identifier, interface, reasoning/effort setting, and permission mode.

## Frozen evaluation routes

For T1–T4 in the OpenAI ecosystem:

- Main: ChatGPT GPT-5.6 Sol, highest reasoning setting actually exposed.
- Executor: Codex GPT-5.6 Terra, xhigh.

For T1–T4 in the Anthropic ecosystem:

- Main: Claude Opus 5, high.
- Executor: Claude Code Sonnet 5, high.

Do not silently substitute a model. An unavailable required identifier is an infrastructure stop and must be recorded.

For T5–T7, Direct and AI-Native receive the same mixed resource pool: Main reasoning; Codex Terra xhigh; Claude Code Sonnet 5 high; Claude Opus 5 high research/reasoning; primary-literature web research; and local terminal/Python/CPU/GPU. Main chooses routing by the work; the harness records the route and does not prescribe a Phase count or solver.

## Routing principles

- Keep Main persistent for goal interpretation, material decisions, acceptance, repair, and replanning.
- Route bounded implementation to Terra or Sonnet with exact paths, authority, return contract, and checks.
- Use fresh independent verification when semantic ambiguity or high-impact evidence warrants it.
- Use the lowest sufficient route for deterministic mechanical work.
- Preserve all durable state in the repository; no role may rely on hidden session memory as the only record.
- Main is not automated through a noninteractive API benchmark loop.

Provider-specific reasoning controls change over time. Sol exposes a reasoning-effort family that includes xhigh/max in the API documentation; the ChatGPT run records the highest setting actually offered by the product. Claude 5 uses current effort/adaptive-thinking controls; do not emulate removed legacy token-budget controls.

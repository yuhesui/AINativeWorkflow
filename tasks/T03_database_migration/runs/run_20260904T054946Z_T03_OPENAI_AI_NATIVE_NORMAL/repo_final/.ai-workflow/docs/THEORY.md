# THEORY.md — Theory Workstream Guide

Theory is a specialist chat/reasoning workstream activated by Main when formal reasoning materially affects the Phase.

Theory may perform mathematical derivation, counterexample search, theorem audit, conceptual interpretation, and literature/novelty analysis. It returns evidence and claim-status recommendations to Main; it does not silently change the DIC, run repository implementation, or release claims.

For material claims, separate positive derivation, hostile audit, and novelty comparison where useful. Preserve assumptions and classify every statement as definition, invariant, theorem/proposition, conjecture, empirical hypothesis, or unsupported/removed.


## Primary-aim discipline

Theory should strengthen or falsify the Phase Primary Aim, not accumulate loosely related lemmas because they are available. A hostile audit is a constraint on correctness, not a substitute objective of making the result maximally defensive. Return the strongest correct central statement, the assumptions it actually needs, and which side results are genuinely load-bearing.

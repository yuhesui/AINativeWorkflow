# CODEX_EXECUTION.md — Codex Orchestrator Overlay

## Role

Codex is used as a repository-aware coding-agent Orchestrator or bounded Worker. It receives the approved Phase/DIC and must not redefine Main's intent or material science.

## Prompt shape

A strong Codex prompt names:

- the desired repository behavior or defect;
- relevant files/symbols or a reproducible failure;
- constraints and protected paths;
- expected output/diff;
- verification commands and acceptance evidence;
- authority and stop boundaries.

Let Codex inspect the repository and choose local implementation details when they are not contractually fixed.

## Execution

- read repository instructions and the active DIC first;
- establish the actual root and working-tree state;
- inspect before editing;
- keep each prompt to one primary outcome and a small coherent package;
- use subagents/worktrees for genuinely independent branches when supported;
- avoid concurrent edits to the same canonical files;
- run focused checks before broader integration checks;
- inspect the final diff and remove temporary files;
- report actual commands, failures, evidence, and caveats.

## Prompt tuning

Orchestrator must adapt each EPS prompt to the active Codex surface and available tools. Do not paste a universal coding prompt unchanged. Expose only relevant tools and state tool/result expectations clearly.

## Stop upward

Return to Main for changes to objective, acceptance, scientific method, protocol, destructive/external authority, paid compute, credentials, public release, or submission.
